## 交付行为

- R1：按 index 组装完整工具列表，支持交错分片和完整名称重发；缺失/重复调用 ID、损坏流与 JSON 尾部额外内容安全失败。可选 reasoning_content 仅在模型协议内回传，不发送给用户或持久化。
- R2：普通 Java 的模型/工具循环，沿用 JDK HttpClient、Spring MVC SseEmitter 和原请求资源所有权。只有 search_knowledge_base，按顺序执行；身份取自认证命令，模型不能指定搜索用户。零搜索可直接回答，资料不足可继续查询。
- 每次下一轮模型请求都携带原调用 ID 对应的完整 assistant/tool 配对。无结果、非法参数、未知工具和可恢复检索失败回填明确结果。当前 user 与工具骨架受保护，旧历史按完整回合删除，过大的工具正文共享截断额度，短结果保留完整正文，所有来源索引保留。来源编号跨调用稳定，同一搜索结果内部去重；再次查询可重新提供正文，防止先前的结果或上下文截断使资料无法补回。
- SSE chunk 带 roundId，round_end 区分 intermediate/final，进度带 callId。当前正文逐段显示，中间说明保留在检索过程；只有 final 正文进入一次保存，取消、非法回合或未完整结束不追加成功回答。
- 默认 3 轮工具、6 次实际执行、连续相同动作第 3 次拦截、10 秒收尾预留、16384 字符工具结果。工具预算触发后关闭工具，仅请求一次带部分完成标记的答案；默认最多 4 次模型请求。全部步骤共享原 300000ms 总期限。

### 多轮与权限

`AgentLoopServiceTest` 覆盖同轮多搜索、原 callId 回填、查询改写、稳定来源编号、未知工具/无效参数/检索错误恢复、3 轮后第 4 次请求无工具、6 次预算后的剩余调用错误回填、重复动作拦截、收尾时间预留、超时/取消、无工具响应违规失败，以及实际后续 HTTP 消息中的多工具上下文截断。第三轮真实模型连接取消后断开，未发后续回合。

`KnowledgeBaseSearchToolTest` 检查模型传入其他用户名不能改变服务端身份；严格参数 JSON 校验、来源去重、正文边界及结果限额。原权限、请求隔离、会话归属、发送失败、提交仲裁与资源测试全部保留。

独立审查后新增 6 个失败回归，修复前 28 项定向测试中 6 项失败；修复过程进一步确认按比例裁剪会丢掉短结果，新增完整短结果断言并复现失败。最终 34 项定向测试全部通过：

## 实施判断与代价

1. 复用已授权设计并自主补齐实施细节，避免重复确认；代价是具体实现取舍由本次代码和测试供用户审阅。
2. 在现有干净工作区创建专用分支，保留已安装依赖；代价是当前 checkout 已切到功能分支。
3. Windows 使用本地日志/台账，保留未提交证据；代价是本地辅助产物仍占磁盘空间，未自动提交或清理。
4. 额外限制工具元数据 4096 字符、每轮默认 16 调用（配置上限 64）、推理 1048576 字符、工具结果默认 16384 字符；代价是过大供应商输出被拒绝或截断。
5. 静态调试页运输模块从 TypeScript 同步生成；代价是协议变化时需执行 frontend 的 sync:chat-transport。
6. 后续验收显式指定本计划的 metrics-dir，避免继续写旧计划目录；代价是验证命令增加一个参数，早期基线仍用了历史默认路径。
7. 最终审查首先选择 gpt-6-astra，但因额度不足未能执行；改用独立的新上下文 gpt-6.1-sol 审查。代价是使用可用模型完成审查，不能宣称最初指定模型已审查。
8. 来源编号跨调用稳定，只在同一次结果内删除重复命中，跨调用重新发送有界正文；代价是重复来源可能占用更多上下文，受共享预算约束。
9. 审查略过的 MCP/并行工具/其他客户端迁移继续不实施；代价是这些能力尚不可用，Reactor 依赖保留。
10. 审查确认基线已有的同名文件冲突、含右括号文件名引用解析、sourceFiles 渲染增长暂不改动；代价是这些旧问题仍存在。
11. 基线已有的模型帧限额与前端单事件限额差异暂不改动；代价是异常大的单个正文分片仍可能被前端拒绝。
12. 不宣称真实供应商决策、检索/存储性能、生产容量及 Java17 实际运行已验证；代价是实际部署仍需针对环境联调。
13. 不检查现有密钥是否有效或生产配置是否可用；只读取配置差异，不调用真实供应商。代价是实际 endpoint/key 仍需用户环境验证。
14. 共享正文截断改为统一长度上限，优先保留短结果；代价是长结果会承担较多裁剪，协议与来源索引仍完整。

独立审查没有待处理 Minor。重要问题按一次修复流程处理，以失败回归和完整测试验证，不再重复派发审查。

## 复现方式

从仓库根目录执行后端完整回归；代理测试需要先启动实际 Nginx，并将它指向测试的 backend-port：

```powershell
mvn '-Dchat.acceptance.metrics-dir=.superpowers/sdd/2026-10-06-knowledge-base-react' test
mvn '-Dtest=ChatStreamingProxyTest' '-Dchat.acceptance.backend-port=<本机后端端口>' '-Dchat.acceptance.proxy-url=http://127.0.0.1:<本机代理端口>' '-Dchat.acceptance.metrics-dir=.superpowers/sdd/2026-10-06-knowledge-base-react' test
mvn '-DskipTests' package
```

前端在 frontend 目录执行 `pnpm sync:chat-transport`、`pnpm test:chat`、`pnpm build`、`pnpm typecheck`。本次实际调用已安装工具脚本，避免包管理器缓存权限影响；对应日志均保留。构建与后端打包不会部署服务。
