# ShadowRAG 前端 P0 Bug 评估报告

> 评估时间：2026-08-06
> 评估范围：`service/request`（拦截器）、`router/guard`（路由守卫）、`store/modules/auth`、`store/modules/chat`、`views/chat`（WebSocket 聊天）、`store/modules/knowledge-base`（上传）、`utils/storage`、`.env*`
> 结论：**前端存在 4 个 P0（3 个安全 + 1 个功能性瘫痪）+ 若干 P1。核心问题是 JWT 明文暴露与聊天消息处理无防御。**

---

## 一、P0 Bug 清单

### 🔴 P0-1：JWT 明文暴露在 WebSocket URL 路径

**位置**：`store/modules/chat/index.ts:19` + 后端 `ChatWebSocketHandler.extractUserId`

**问题**：
```ts
useWebSocket(`/proxy-ws/chat/${store.token}`, { autoReconnect: true })
```
JWT 直接拼进 URL 路径，后端也从 path 最后一段取 token。token 会泄露到：
- **反向代理 access log**（Nginx 默认记录完整 URL）
- **浏览器历史 / cache**
- **Referer header**（若页面跳转外链，token 会被带到第三方）

**影响**：token 泄露 = 在 token 有效期内账号被完全接管。生产环境这是高危。

**建议修复**：
- WebSocket 改用 `Sec-WebSocket-Protocol` 头或自定义 header 传 token（需后端握手时读取）。
- 或握手时用一次性 ticket（前端先 HTTP 换 ticket，再用 ticket 建 WS），ticket 用一次即失效。
- 退一步：至少保证 WS 不经过会记录 URL 的中间层，且禁止页面外链跳转带 Referer（`Referrer-Policy: no-referrer`）。

### 🔴 P0-2：XSS —— 来源文件名未转义直接拼 HTML

**位置**：`views/chat/modules/chat-message.vue:23-41` `processSourceLinks`

**问题**：
```ts
return `(来源#${sourceNum}: <span class="${linkClass}" data-file-id="${fileId}">${fileName}</span>)`;
```
`fileName` 来自 LLM 输出（基于检索的文档引用），**未经任何 HTML 转义**直接插入 HTML 字符串，再交给 `VueMarkdownIt` 渲染。`source-file-link` 样式生效说明 raw HTML 被透传渲染。

**攻击路径**：
1. 攻击者上传一个文件名含 `<img src=x onerror=alert(document.cookie)>` 的文档（或文档内容含恶意 payload）。
2. 用户提问，LLM 检索到该文档并在引用里原样输出文件名。
3. `processSourceLinks` 把含 payload 的文件名拼进 `<span>` → markdown 渲染器透传 → `onerror` 执行 → XSS。

**影响**：窃取 token（localStorage 里的 `token`/`refreshToken`）、冒充用户发请求、横向越权。

**建议修复**：
- 对 `fileName` 做 HTML 转义（`&`/`<`/`>`/`"`/`'`）后再拼接。
- 更好：不要手拼 HTML，改用 markdown 语法（`[文件名](#)`）让渲染器统一处理，或用 Vue 组件插槽渲染链接。
- 同时给 `VueMarkdownIt` 显式关闭 raw HTML（`html: false`）或配白名单 sanitizer。

### 🔴 P0-3：`wsData` JSON.parse 无 try/catch，单条异常消息致聊天瘫痪

**位置**：`views/chat/modules/input-box.vue:19-33`

**问题**：
```ts
watch(wsData, val => {
  const data = JSON.parse(val);   // 无 try/catch
  ...
});
```
任何**非 JSON 格式**的 WS 消息（连接异常文本、心跳、代理错误页、半截消息）都会让 `JSON.parse` 抛错。Vue 的 watch 回调抛错会被捕获但**该次及后续 watcher 行为不可预期**，实际表现往往是该 watcher 失效 → 之后所有流式 chunk/completion 事件都不再处理 → 聊天界面彻底卡死，只能刷新页面。

**影响**：一次异常消息即瘫痪整个聊天，稳定性 P0。

**建议修复**：
```ts
watch(wsData, val => {
  let data;
  try { data = JSON.parse(val); } catch { return; }  // 忽略非 JSON
  ...
});
```

### 🔴 P0-4：文件下载接口把 token 明文放 query 参数

**位置**：`views/chat/modules/chat-message.vue:98-105` `handleSourceFileClick`

**问题**：
```ts
const { error, data } = await request({
  url: 'documents/download',
  params: { fileName: decodedFileName, token: authStore.token },  // token 在 query
  baseURL: '/proxy-api'
});
```
token 出现在 URL query string，同样进 access log / Referer / 浏览器历史。与 P0-1 同类的泄露。

**影响**：token 泄露 → 账号接管。

**建议修复**：
- token 走 `Authorization` 头（拦截器已自动加），query 里不要重复传 token。
- 后端下载接口从 header 取 token 校验，而非 query。

## 二、P1 问题（非 P0 但需尽快修）

### 🟠 P1-1：token 刷新竞态可能导致频繁登出
**位置**：`service/request/shared.ts:30-42`

多个 401 请求并发时，用 `state.refreshTokenFn` 去重，但 `setTimeout(() => { state.refreshTokenFn = null; }, 1000)` 在 1 秒后清空引用。若首次刷新耗时 >1s（网络慢），1 秒后有新的 401 会发起**第二次刷新**，用同一个（可能已失效的）refreshToken → 若后端 refreshToken 是一次性的，第二次必失败 → 用户被登出。

**建议**：`refreshTokenFn` 在 promise resolve/reject 后再清空，而非固定 1 秒。

### 🟠 P1-2：停止响应前后端语义不一致（关联后端 P0）
前端点停止后立即 `assistant.status = 'finished'`，但后端 `stopFlags` 不真正中断 LLM 流，后续 chunk 仍会到达并把 status 改回 `loading`，导致消息状态闪烁。根因在后端（见 Agentic RAG 报告 Bug 2），前端表现是症状。

### 🟠 P1-3：上传断点信息无持久化，刷新即丢失
**位置**：`store/modules/knowledge-base/index.ts`

`tasks` / `uploadedChunks` 只存在内存。页面刷新后全部丢失，"断点续传"名不副实——实际只是会话内重试。大文件上传中刷新 = 从头再来。

### 🟠 P1-4：`apifoxToken` 硬编码在请求头
**位置**：`service/request/index.ts:18`
```ts
headers: { apifoxToken: 'FY65Vng88xra_BveQ5E_4' }
```
应移到 env 或删除（生产环境无用且泄露内部工具信息）。

### 🟠 P1-5：上传完成判断用 `uploadedChunks.length === totalChunks` 不严谨
**位置**：`store/modules/knowledge-base/index.ts:47`
若后端返回的 `uploaded` 数组含重复 chunkIndex，`length` 会虚高导致误判完成，触发提前 merge。应按 Set 去重或校验覆盖所有索引。

### 🟠 P1-6：`calculateMD5` 对大文件全量读入内存
大文件（几百 MB）整文件读入算 MD5 易致浏览器 OOM。应分片增量哈希（spark-md5 的 incremental 模式）。

## 三、优先级

| 级别 | 事项 | 类型 |
|------|------|------|
| P0 | 1 JWT 明文暴露在 WS URL | 安全 |
| P0 | 2 XSS：来源文件名未转义 | 安全 |
| P0 | 3 wsData JSON.parse 无保护 | 功能瘫痪 |
| P0 | 4 下载接口 token 放 query | 安全 |
| P1 | token 刷新竞态、停止语义、断点不持久化、apifoxToken、上传完成判断、MD5 OOM | 功能/安全 |
